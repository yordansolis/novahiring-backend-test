# Proceso de Evaluación de Candidatos

## Capa 1 — Discovery(Descubrimiento) con el Cliente

Antes de evaluar cualquier candidato, tu empresa debe entender qué quiere construir el cliente. Eso incluye:

- **Problema de negocio real**: ¿Qué problema necesitan resolver? (ej: mejorar atención al cliente, automatizar análisis de datos, scraping, etc.)
- **Reglas de negocio**: ¿Qué tan definidas están?
- **Arquitectura existente**: ¿Tienen sistema actual o es un proyecto legacy?
- **Restricciones**: Presupuesto, tiempo, equipo actual, compliance
- **Nivel de autonomía esperado**: ¿Solo ejecución o también diseño?

> Con esto construyes un perfil de candidato a medida, no uno genérico.

---

## Capa 2 — Evaluación del Candidato

Recién aquí entra el chatbot, pero con preguntas, escenarios y criterios calibrados al caso de uso real del cliente.

### Ejemplos de evaluación según el tipo de cliente:

| Cliente busca | Evaluar en el candidato |
|--------------|-------------------------|
| Chatbot para call center | NLP, flujos conversacionales, integraciones con CRMs, manejo de estados de conversación |
| Scraping + análisis | BeautifulSoup, Scrapy, manejo de datos con pandas, pipelines, visualización |
| Sistema de datos | Arquitectura de datos, ETL, bases de datos, ML básico |

---

## Punto Clave

> Un **Senior Full-Stack** no es un perfil único. Es un contenedor que se llena según el contexto. El mismo título puede significar cosas completamente distintas dependiendo del problema que el cliente necesita resolver.
